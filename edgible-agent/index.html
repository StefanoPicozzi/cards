What it protects

  • Made on your machine, seen by nobody: LITELLM_KEY_AGENT, LITELLM_DB_PASSWORD and LITELLM_SALT_KEY. The card makes them at first start, and only its own apps read them. They stay on the machine, and in its backups.
  • For you: OPENCLAW_GATEWAY_TOKEN: the Control UI without OPENCLAW_USERS, pasted once per browser; with it, OpenClaw's own command line only. Made on your machine too, where the show command in the README prints it.
  • For you: LITELLM_MASTER_KEY: the AI gateway's admin and its keys; the agent has its own key, never this one. Made on your machine too, where the show command in the README prints it.
  • You bring, into card.env on your machine: OPENCLAW_MODEL_KEY (optional), from a shared AI gateway, by edgible-mcp's gateway_key (organisation secret <app>-gateway); GEMINI_API_KEY (optional), from https://aistudio.google.com/apikey (free tier), for the gateway's fast fallback; DEEPSEEK_API_KEY (optional), from https://platform.deepseek.com/api_keys, for the gateway's fast and smart; OPENROUTER_API_KEY (optional), from https://openrouter.ai/settings/keys, for open (one key, many open models); ANTHROPIC_API_KEY (optional), from https://console.anthropic.com/settings/keys, for the gateway's best (Claude).

Why

Most people trying an AI agent want it to do things for them, not just chat. This pattern gives you one: OpenClaw, on a machine you own, that also looks after your Edgible apps. From your phone you can ask it what is running and whether each app answers, have it find a card for a need, and, if you allow it, have it deploy, move or remove apps, each change asked of you first. It is built from the openclaw and edgible-mcp app cards.

What

Four parts on one machine, in one Compose project. openclaw is OpenClaw's Gateway and Control UI, published as openclaw on org, then OpenClaw's Gateway token and device approval, as in the openclaw card. edgible-mcp is Edgible's MCP server, with no address of its own: OpenClaw reaches it on the project's network, and nothing else can. On the first Start, openclaw-setup onboards OpenClaw, adds edgible-mcp's tools as the MCP server edgible, and installs the edgible-cards skill from card-kit, so the agent knows the honest-advice rules as well as the tools. The tools only read unless EDGIBLE_MCP_ALLOW_WRITE=1; then deploy_card, move_card and remove_card ask first, each change is recorded as made by OpenClaw, and EDGIBLE_MCP_DEVICES limits which devices may change. The agent acts as the Edgible CLI inside edgible-mcp, signed in once after Start: sign it in as an account that may do what you allow. litellm is the AI gateway from the litellm card, with no address of its own: it holds the provider keys you bring and serves models by purpose, fast (DeepSeek, falling back to Gemini Flash), smart, best (Claude Opus, with an Anthropic key), and private and private-smart (models on this machine, such as ollama-osx's). OpenClaw asks it for OPENCLAW_MODEL (fast by default) with a key of its own, made on the machine and registered with a budget (LITELLM_APP_BUDGET dollars per LITELLM_APP_BUDGET_PERIOD); the gateway's own secrets are in a volume OpenClaw never sees, so the agent cannot spend past its budget. You bring each provider's key once, to the gateway, never to the agent. To share one gateway between agents and machines instead, with one admin showing everyone's spend, leave COMPOSE_PROFILES empty: this pattern then runs no gateway of its own, and the agent uses the shared one at OPENCLAW_MODEL_URL (the litellm card's litellm-api address plus /v1) with its key in OPENCLAW_MODEL_KEY, which edgible-mcp's gateway_key makes and stores for a deploy to pass by reference.

The agent's config, memory, sessions and workspace live in openclaw-data, and provider sign-in profiles in openclaw-secrets: back them up. edgible-mcp-login holds the CLI's sign-in (lost, sign in again), edgible-mcp-data the record of what the tools did, and edgible-mcp-cache the catalog. Minimum recommended for the place agent: 4 GB of memory and 3.5 GB of disk, on an arm64 or amd64 machine, with no GPU.

The Compose file is docker-compose.yml, the settings card.env, the card card.yml, and the last test test.yml.

How

Five steps. Edit card.env before you start.

1. Fetch

mkdir -p edgible-agent
curl -fsSL https://github.com/edgible-org/cards/archive/refs/heads/main.tar.gz \
  | tar -xz --strip-components=2 -C edgible-agent cards-main/edgible-agent

2. Edit card.env

Set DEVICE, ORG_LABEL, and a provider key or two for the gateway: DEEPSEEK_API_KEY (https://platform.deepseek.com/api_keys, cents a day) for fast and smart, GEMINI_API_KEY (https://aistudio.google.com/apikey, a free tier) for fast's fallback. The models behind each purpose are the LITELLM_*_MODEL lines. Set OPENCLAW_USERS to the Edgible accounts that may use it, by email: then Edgible's sign-in is the only lock, with no token to paste and no browser to approve on the machine. Left empty, Start makes a Gateway token on the machine, which each browser pastes once, and each new browser waits for approval. The gateway falls back to Gemini Flash when DeepSeek fails; set OPENCLAW_MODEL=private to keep every word on this machine with ollama-osx (free, but weak with tools). Set EDGIBLE_MCP_ALLOW_WRITE=1 to let the agent deploy, move and remove apps, and EDGIBLE_MCP_DEVICES to keep it to some devices, such as a test machine.

nano edgible-agent/card.env

3. Check

curl -fsSLo check-env.py https://raw.githubusercontent.com/edgible-org/card-kit/main/check-env.py
python3 check-env.py edgible-agent

It fills each empty secret and moves a taken port, as lines to paste. Run it again until it says no conflicts.

4. Start

docker compose --env-file edgible-agent/card.env -f edgible-agent/docker-compose.yml pull
docker compose --env-file edgible-agent/card.env -f edgible-agent/docker-compose.yml up -d --wait
docker compose --env-file edgible-agent/card.env -f edgible-agent/docker-compose.yml ps

The first start downloads the app's images from the registries named in the Compose file: about 2.1 GB, ten minutes or more on a typical home connection. pull does that download on its own, so you can see it. The time is the download, not Edgible, and it happens once: later starts and upgrades reuse the images on the machine and fetch only what changed. --wait returns when each service is running, and healthy when it has a healthcheck. Then sign the Edgible tools in, once. The easy way needs no shell: ask the agent something that needs Edgible, such as "What Edgible apps are running?", and it answers with a link and a code (edgible-mcp's sign_in); open the link on any device, check the code, and approve with your Edgible login, then ask again. Or on the machine: docker compose --env-file edgible-agent/card.env -f edgible-agent/docker-compose.yml exec edgible-mcp edgible auth login --no-browser prints the same link and code. Change OpenClaw's settings later through openclaw-cli, always with --no-deps, as in the openclaw card.

5. Publish

set -euo pipefail
set -a
. edgible-agent/card.env
set +a
device_id=$(edgible device list --json | jq -er --arg name "$DEVICE" '
  map(select(.name == $name))
  | if length == 1 then .[0].id
    else error("need exactly one device named " + $name + " (" + (map(.status + " " + .id) | join(", ")) + ")")
    end
')
edgible app create existing \
  --non-interactive \
  --name openclaw \
  --port "$OPENCLAW_PORT" \
  --protocol https \
  --auth-modes org \
  --device-id "$device_id"
edgible app list

Without Edgible: only Publish is Edgible's. The app listens on 127.0.0.1 at the port in card.env, so any reverse proxy or tunnel on the machine, such as Caddy, nginx, Cloudflare Tunnel or Tailscale, can publish it instead, and sign-in is then that tool's to provide. Every other step stays the same.

Verify

openclaw uses org.

curl -sS -o /dev/null -w '%{http_code} %{redirect_url}\n' "https://<openclaw hostname>"

That prints 302 and an edgible.com/application-access/ address, so the org sign-in is in front. With OPENCLAW_USERS set, open the hostname on your phone and sign in with Edgible as one of those accounts: OpenClaw lets you in and approves that browser. Without it, open the hostname on your phone and sign in; open https://<openclaw hostname>/#token=<OPENCLAW_GATEWAY_TOKEN> once in that browser (docker compose --env-file edgible-agent/card.env -f edgible-agent/docker-compose.yml run --rm --no-deps openclaw-secrets show OPENCLAW_GATEWAY_TOKEN prints the token, which the card made on the machine); approve the browser on the machine: docker compose --env-file edgible-agent/card.env -f edgible-agent/docker-compose.yml run --rm --no-deps openclaw-cli devices list, then devices approve <requestId>. Start a chat and ask "What Edgible apps are running?".

The rest of the setup is in the OpenClaw docs docs.

Tear down

Four steps, in this order. Step 1 runs wherever edgible is logged in. Steps 2 to 4 run on the machine that runs the containers. Steps 2 and 3 read card.env, so keep it until step 4.

1. Unpublish

edgible app delete openclaw --yes

2. Stop

docker compose --env-file edgible-agent/card.env -f edgible-agent/docker-compose.yml down

3. Delete the data

Skip this step to keep the data. The loop copies each volume to a .tgz file in this directory first.

for volume in $(docker volume ls -q --filter label=com.docker.compose.project=edgible-agent); do
  docker run --rm -v "$volume:/data:ro" -v "$PWD:/backup" alpine tar -czf "/backup/$volume.tgz" -C /data .
done
docker compose --env-file edgible-agent/card.env -f edgible-agent/docker-compose.yml down --volumes

4. Remove the card

rm -rf edgible-agent
