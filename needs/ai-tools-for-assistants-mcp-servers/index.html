AI tools for assistants (MCP servers)

Self-hosted alternatives to Zapier MCP.

What people say

  • let Claude or ChatGPT use my files or database
  • use my MCP server when I'm away from my desk
  • use my MCP server from Claude on my phone
  • share an MCP server with my team
  • give my AI assistant access to our internal tools
  • host the MCP server I built
  • manage Edgible from Claude or Cursor

Why people self-host it

People leave hosted MCP platforms, Zapier MCP, keeping the server on one laptop for it. Why, strongest first: privacy, control, it has to run at home.

Does it suit a machine of your own?

Good fit an MCP server is a small web service next to the data it reaches, which is what Edgible publishes; what decides it is how the person's assistant signs in

Questions that decide it

  • which assistant will connect to it: Claude Code, Claude's apps (desktop, web, phone), or something else?
  • should it only read, or also change things?
  • who besides you should get in?

How to publish it

Usually
for Claude's web, desktop and phone apps (custom connectors, which need OAuth): the server unpublished, behind the mcp-signin card, which signs people in with Edgible (mcp-signin on none, mcp-signin-login on org); for clients that send a header (Claude Code and most developer tools: Authorization: Bearer): api-key, one key per person
When the data is private or sensitive
mcp-signin with MCP_SIGNIN_USERS listing who may sign in, or api-key with one key per person so a key can be revoked; read-only tools unless writes are needed; never the server itself on none

Who sees what inside it

every tool the server offers is something the assistant can do with the person's data; offer read-only tools first, and ask before tools that change or delete things

The machine

next to the data or tools it reaches; always on if others use it. Most packaged servers speak stdio, so publishing one needs a bridge container that serves it over Streamable HTTP; a server that already speaks HTTP needs none

For builders

the quickest way to let early users try an MCP server: publish it from the developer's machine or a small cloud server, without building hosting
