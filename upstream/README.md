# Upstream requests

Things the cards' testing shows the authors of an app could change, written so each can be pasted
into an issue on the app's own project. Nothing here has been sent unless its status says so.

Each file has a header:

```
app:      the app, as in its card
project:  where its issues are filed
status:   draft | sent | resolved | wontfix
found:    YYYY-MM-DD
sent:     link to the issue, once filed
```

A file is a request, not a verdict: what the card does today, what a change would let the card
drop, and what was checked in the app's own source. Add a file when a card carries a workaround
that a small change upstream would remove. Do not put anything here that is not already public: a
vulnerability nobody knows about goes to the author privately first.
