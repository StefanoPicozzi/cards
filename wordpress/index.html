What it keeps

Its data is in the volumes wordpress-files, wordpress-db-data and wordpress-secrets. The card does not say yet which of them hold what only you have, so back them all up.

What it protects

  • Made on your machine, seen by nobody: WORDPRESS_DB_PASSWORD. The card makes them at first start, and only its own apps read them. They stay on the machine, and in its backups.
  • For you: WORDPRESS_ADMIN_PASSWORD: admin's sign-in, set by prepare.sh. Made on your machine too, where the show command in the README prints it.

Why

WordPress runs a large share of the web, and most of it sits with a host you pay every month. WordPress runs just as well on a machine you own, with the database beside it.

What

One app, wordpress, on the place wordpress, on none: it is a public site. Its admin, /wp-admin, is on the same hostname, because WordPress sends every request to its one address; Edgible's auth is per hostname, so the admin cannot be put behind org on its own. WordPress's login protects it, and the admin password is generated, not chosen.

WordPress keeps its address in its settings, so WP_HOME and WP_SITEURL are https://wordpress.<ORG_LABEL>.<EDGIBLE_DOMAIN>, or WORDPRESS_URL on your own domain. A fresh WordPress hands its admin to whoever opens the install page first, so this card installs it from the command line before it is published, with the wordpress-cli service, which runs only when asked.

The images are wordpress:7.1.3-php8.3-apache, mariadb:11.8.9, and wordpress:cli-2.12.0-php8.3. To use it in a card, copy the four services, the x-wordpress-env block, the three volumes, card.yml's secrets:, and the WORDPRESS_ lines.

Themes, plugins and uploads live in the volume wordpress-files, and posts, pages and users in wordpress-db-data. Minimum recommended for the place wordpress: 384 MB of memory and 2 GB of disk, on an arm64 or amd64 machine, with no GPU.

The Compose file is docker-compose.yml, the settings card.env, the card card.yml, and the last test test.yml.

How

Five steps. Edit card.env before you start.

1. Fetch

mkdir -p wordpress
curl -fsSL https://github.com/edgible-org/cards/archive/refs/heads/main.tar.gz \
  | tar -xz --strip-components=2 -C wordpress cards-main/wordpress

2. Edit card.env

Set DEVICE to a name edgible device list prints, ORG_LABEL to the part after the app name in a hostname edgible app list prints, and WORDPRESS_ADMIN_EMAIL to your address. There are no passwords to fill: Start makes them on the machine.

nano wordpress/card.env

3. Check

curl -fsSLo check-env.py https://raw.githubusercontent.com/edgible-org/card-kit/main/check-env.py
python3 check-env.py wordpress

It moves a taken port, as lines to paste. Run it again until it says no conflicts.

4. Start

docker compose --env-file wordpress/card.env -f wordpress/docker-compose.yml pull
docker compose --env-file wordpress/card.env -f wordpress/docker-compose.yml up -d --wait
docker compose --env-file wordpress/card.env -f wordpress/docker-compose.yml ps

The first start downloads the app's images from the registries named in the Compose file: about 372 MB, a minute or two on a typical home connection. pull does that download on its own, so you can see it. The time is the download, not Edgible, and it happens once: later starts and upgrades reuse the images on the machine and fetch only what changed. --wait returns when each service is running, and healthy when it has a healthcheck. Then install WordPress, before Publish, so its install page is never public:

sh wordpress/prepare.sh

prepare.sh is:

#!/bin/sh
# Prepare for the wordpress card: install WordPress, so its install page is never public.
# Run it after Start and before Publish, from the directory that holds wordpress/:
#   sh wordpress/prepare.sh
set -eu
cd "$(dirname "$0")"
set -a; . ./card.env; set +a
COMPOSE=${COMPOSE:-docker compose --env-file card.env -f docker-compose.yml}

# The card made this password on this machine at Start (wordpress-secrets).
WORDPRESS_ADMIN_PASSWORD=$($COMPOSE run --rm --no-deps wordpress-secrets show WORDPRESS_ADMIN_PASSWORD)

$COMPOSE --profile cli run --rm -T wordpress-cli \
  wp core install --url="${WORDPRESS_URL:-https://wordpress.$ORG_LABEL.${EDGIBLE_DOMAIN:-edgible.app}}" --title="My site" \
  --admin_user=admin --admin_password="$WORDPRESS_ADMIN_PASSWORD" --admin_email="$WORDPRESS_ADMIN_EMAIL" --skip-email

It prints Success: WordPress installed successfully. The admin user is admin, with the password the card made on the machine; see it with docker compose --env-file wordpress/card.env -f wordpress/docker-compose.yml run --rm --no-deps wordpress-secrets show WORDPRESS_ADMIN_PASSWORD.

5. Publish

set -euo pipefail
set -a
. wordpress/card.env
set +a
device_id=$(edgible device list --json | jq -er --arg name "$DEVICE" '
  map(select(.name == $name))
  | if length == 1 then .[0].id
    else error("need exactly one device named " + $name + " (" + (map(.status + " " + .id) | join(", ")) + ")")
    end
')
edgible app create existing \
  --non-interactive \
  --name wordpress \
  --port "$WORDPRESS_PORT" \
  --protocol https \
  --auth-modes none \
  --device-id "$device_id"
edgible app list

Verify

wordpress uses none.

curl -sS -o /dev/null -w '%{http_code}\n' "https://<wordpress hostname>"

That prints 200: the installed site. An uninstalled one would answer 302 to its install page. Open https://<wordpress hostname>/wp-admin and sign in as admin with the password the card made, which the show command in Start prints.

The rest of the setup is in the WordPress docs.

Tear down

Four steps, in this order. Step 1 runs wherever edgible is logged in. Steps 2 to 4 run on the machine that runs the containers. Steps 2 and 3 read card.env, so keep it until step 4.

1. Unpublish

edgible app delete wordpress --yes

2. Stop

docker compose --env-file wordpress/card.env -f wordpress/docker-compose.yml down

3. Delete the data

Skip this step to keep the data. The loop copies each volume to a .tgz file in this directory first. wordpress-secrets.tgz holds the card's passwords and keys: keep it as safe as the data, which needs them.

for volume in $(docker volume ls -q --filter label=com.docker.compose.project=wordpress); do
  docker run --rm -v "$volume:/data:ro" -v "$PWD:/backup" alpine tar -czf "/backup/$volume.tgz" -C /data .
done
docker compose --env-file wordpress/card.env -f wordpress/docker-compose.yml down --volumes

4. Remove the card

rm -rf wordpress
